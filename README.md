# 千词斩APP



## 1. 产品介绍

这是一个背单词的web应用。 

* 单词表：用户可以从**高考词汇**和**四级词汇**中自由选择一个单词表进行学习。
* 单词推送：对于每日推送的新单词，如果用户认识该单词，则不再推送；如果不认识，则会在次日及以后重新推送给用户进行复习
* 签到管理：用户单日复习+新学习达到50个单词时，用户单日签到成功。签到有积分奖励，规则如下：
  * 日常签到：+10分
  * 两日连续签到：+5分
  * 五日连续签到：+20分
  * 十日连续签到：+50分
  * 二十日连续签到：+200分



## 2. 技术选型

* 语言：Golang 1.26
* 后端框架：Gin
* 持久化存储：MySQL
* ORM：GORM
* 缓存：Redis



## 3. 后端API介绍

### "/login" 登录注册

用户登录注册一体，用户只需输入账号密码。

如果该用户名已经注册，则检查密码并自动登录；如果该用户名还未注册，则自动注册该用户名+密码。

#### POST方法

* 请求头：登录注册页面无需token，因为还未登陆

* 请求体：需要使用form表单向后端传递用户名与密码。字段如下

  * "userName"：用户名，字符串类型
  * "password"：密码，字符串类型

* 返回内容：

  * 用户名或密码为空：返回值401

    ```
    {
    	"code":2,
    	"info":"empty password or username"
    }
    ```

  * 登录token发放失败：返回值500

    ```
    {
    	"code":-4,
    	"info":"token发放失败"
    }
    ```

  * 密码错误：返回值401

    ```
    {
    	"code":2,
    	"info":"Wrong password"
    }
    ```

  * 登录\注册成功：返回值200

    ```
    {
    	"code":0,
    	"info":"Succeed",
    	"token":token
    }
    ```



### "/index" 用户主界面

该界面是用户登录注册后自动跳转的页面。展示内容包括高考和四级两张单词表的学习进度与总单词数

只需提供选择单词表学习的入口即可，给两个按钮，分别跳转到"GET /study/cee"和"GET /study/cet4"

#### GET方法

* 请求头：需要Bearer token。

* 请求体：无

* 返回内容：返回值200

  ```
  {
      "cee_progress": 10,
      "cee_total": 3933,
      "cet4_progress": 11,
      "cet4_total": 2674,
      "code": 0,
      "info": "获取用户进度成功"
  }
  ```

### "/study/:alphabet" 高考单词学习界面

这是最主要的单词学习URL。主要功能在此展开。

所有的学习进度记录、需复习词汇等功能均由后端控制，前端只需发出get或post请求即可

注：:alphabet为URL参数，可选"cee"或"cet4"，分别对应高考单词和四级单词学习



#### GET方法

从当前单词表中自动获取需复习词汇以及新词汇。

如果该单词表仍然存在需要复习的单词，则在复习完成前不会推送新单词。

如果所有单词均已经复习完，或没有需要复习的单词，则可以推送新单词。

* 请求头：需要Bearer token。
* 请求体：无
* 返回内容：返回值200

```
{
    "code": 0,
    "english": "antique ",
    "info": "新词汇",
    "isReview": false,
    "word_id": 11
}
```

解释一下返回JSON的含义：

* "english"：下一个学习词汇的英文
* "isReview"：bool类型，声明这是不是复习词汇，需要在前端体现
* "word_id"：当前词汇的id



假设当前单词表已经全部学完：直接返回200，需要在前端自动跳转回"/index"

```
{
	"code":     0,
	"info":     "单词表已学完",
	"word_id":  cur_progress_int,
}
```





#### POST方法

post请求是在调用完get并得到当前单词的具体信息后，由用户判断这个单词认不认识，并发送状态。

在发出get请求并获得当前需要学习的单词后，用户可以选择“认识”或“不认识”。

如果选择“认识”，则该单词以后不会复习；如果“不认识”，次日及以后还会复习，直到学会才不继续推送。

* 请求头：需要Bearer token。

* 请求体

  ```
  {
      "WordID": 23,
      "Understand":true
  }
  ```

  * "WordID"：当前学习的单词id，需要前端在调用get请求后记录一下
  * "Understand"：bool类型，表示这个单词会不会

* 返回内容：返回值200

  ```
  {
      "chinese": "n.古董",
      "code": 0,
      "english": "antique ",
      "info": "已记录进度",
      "progress": 11
  }
  ```

  *  不管会还是不会，统一返回格式
  * "chinese"：当前单词的汉语翻译
  * "english"：当前单词的英文
  * "progress"：当前用户当前单词表的学习进度



#### 页面设计

* GET方法有两种请求地点：

  * /index主界面，具有两个按钮，分别可选择两张单词表，点击后发起"GET: /study/:alphabet" 请求
  * /study/:alphabet学习界面，在post请求结束后，会自动调用"GET: /study/:alphabet"请求获取下一个需要学习的单词

* POST方法的请求地点：

  * /study/:alphabet学习界面，在get请求完单词后，由用户选择认不认识这个单词，"认识"和"不认识"都对应post请求，只不过请求体的"Understand"字段，前者是true，后者是false

  

### "/sign/:YYYYmm" 按年月获取签到记录

这个请求，从"/info"界面下多一个按键出来，专门跳转到签到记录页面

这个页面中，用户可以选择年月（如202607），前端需要显示当月的签到记录，以及截至目前为止的连续签到天数

注：":YYYYmm"是URL参数，代表某年某月，比如202607

#### GET方法

* 请求头：Bearer token

* 请求体：无

* 返回内容：返回值200

  ```
  {
      "bitsStr": "0000000000000000000000001100000",
      "code": 0,
      "constantSignedDays": 2,
      "info": "获取该月签到记录成功！"
  }
  ```

  * "bitsStr"：当月的签到情况，用01字符串表示，0表示当天未签到，1表示当天签到
  * "constantSignedDays"：截至当天连续签到天数
